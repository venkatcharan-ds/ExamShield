3-Stage Risk Formula

Stage 1 · ML Assessment
Anomaly Score → 0–55
Piecewise percentile mapping from Isolation Forest raw score. Training distribution defines thresholds. Window-level ML assessment.
Stage 2 · Rule Boost
max(ML, rule_score) → 0–84
Deterministic rule engine evaluates tab switches, paste events, copy events, idle duration. Score = max of ML or rule output, ensuring rule signals aren't masked.
Stage 3 · Synergy Boost
+10 when ML > 35 AND Rule > 60 → cap 99
Synergy bonus fires only when both the anomaly model AND the rule engine independently flag the session — co-occurring signals that would rarely appear in legitimate exam behavior.

Innovation + Privacy

Consent Firewall

Consent is frozen at grant time as original_context. Authorization is always evaluated against the frozen snapshot, never the current context — making retroactive scope creep impossible at the code level.

ConsentFirewall.authorize()
→ checks original_context
→ NOT current_context
→ frozen at consent grant

Drift Detection

DriftDetector is stateless — no database, no config. Every evaluation compares consent snapshot against runtime context. Four classification states with distinct recommended actions.

ALIGNED — score 100
MINOR_DRIFT — score 85
SIGNIFICANT_DRIFT — score 15–70
CONSENT_INVALID — score 0

Privacy-First Architecture

No cameras. No audio. No full keystroke logging. Behavioral signals are statistical aggregates, not recordings. Zero PII in the ML feature vector.

Keystrokes anonymized — 'char' or key name only
No biometric data collection
Service-role key never exposed to browser
Session data in-memory only, not persisted
NEXT_PUBLIC_* never includes secrets
